SYNOPSIS
pure elemental subroutine str_to_real(str, val, ierr) 

        character(len=*), intent(in)  :: str
        real(real64),     intent(out) :: val
        integer,          intent(out) :: ierr

DESCRIPTION

STR_TO_REAL(3f) returns a numeric value given a string representing a numeric value; without using internal I/O (the conventional method in Fortran).

The procedure utilitizes full IEEE 754 support for literal Inf/Infinity, NaN (case-insensitive), and signed -0.0 preservation, while keeping the procedure pure elemental.

STR_TO_REAL(3f) works with any G‐format input, This includes whole number, float, and exponential syntax. That is, input strings may contain signs (+/-), decimal points, and scientific notation (e/E/d/D).

The output is a double-precision real (real(real64)), along with an integer error flag (ierr).

OPTIONS
chars input string to read numeric value from

RETURNS
valu DOUBLEPRECISION numeric value returned.
ierr error flag (0 == no error)

    KEY FEATURES OF THIS IMPLEMENTATION

o ASCII Digit Conversion. Uses iachar(c) - iachar(’0’) rather than hardcoded ASCII offsets like 48 to stay portable across compiler environments.
o No Internal I/O Overhead. Avoids Fortran’s internal READ(3f) statement, making it faster in tight loops and safe to use inside pure or elemental procedures or inside parallel OpenMP/GPU regions where I/O is restricted.
o Error Handling (ierr). Safely catches empty strings (1), misplaced decimals (2), malformed exponents (3 or 5), and stray non-numeric characters (4) without crashing the program.
o The subroutine is pure (and elemental) so it can process arrays directly, To maintain this feature the first and last non-space character indices are located directly on the input, avoiding dynamic heap allocation. The intent is to keeps the procedure completely side-effect-free and reasonably fast while providing input valication.

Pure procedures are required for optimal performance or even appearance iin do concurrent loops, OpenMP simd/target regions, or directly on multi-dimensional string arrays.

o Zero Heap Allocations. This avoids allocating memory inside the procedure and keeps the CPU cache footprint minimal.
o overflow protection uses Fortran intrinsic inquiry functions (huge(), maxexponent(), and minexponent()) rather than hardcoded magic numbers.

overflow is guarded agains in in three places:
 
1. The Exponent Integer (exp_val): Prevents integer overflow if a malicious or malformed string has a massive exponent like 1e99999999999.
2. The Mantissa (int_part): This prevents floating-point overflow before the exponent is even applied (e.g., a 400-digit string with no e marker).
e. The Final Scaled Result (val):
  Checks the combined order of magnitude against maxexponent(val) before raising 10.0 to a power that would produce Infinity or trigger a floating-point exception.

    SUMMARY OF PROTECTIONS ADDED

Error Code 6 (Numeric Overflow): Returned cleanly as Infinity without halting execution if the value exceeds huge(1.0_real64) (~1.79769e308).

Exact Edge-Case Checking at 10^308: Distinguishes between valid numbers near the ceiling (such as "1.79e308") and overflowing numbers at the same order of magnitude (such as "1.80e308").

Subnormal / Underflow Handling: Numbers smaller than ~10^-324 underflow cleanly to 0.0_real64. Numbers in the subnormal range (10^-308 to 10^-324) are scaled in two steps (1.0e-300 first) so 10.0_real64 ** exp does not prematurely evaluate to zero before multiplying by the mantissa.

Zero-Mantissa Safety: Inputs like "0.0e5000" evaluate to 0.0_real64 with ierr = 0 rather than falsely triggering an overflow.

Case-Insensitive Inf, Infinity, and NaN: After parsing any leading + or - sign, the subroutine checks if the remaining substring is up to 8 characters long and matches ’INF’, ’INFINITY’, or ’NAN’ in any letter case (e.g., "-Infinity", "+inf", "NaN"). It returns ierr = 0 alongside the corresponding IEEE value.

Signed Zero Preservation (-0.0): Added a signed_zero(sign_val) helper using ieee_negative_zero. Inputs like "-0.0", "-0e500", or negative underflows like "-1.0e-400" now preserve their negative sign bit.

Allocation-Free Uppercasing: Used a fixed-length 8-character helper (to_upper_8) rather than deferred-length allocatable strings so the subroutine remains fast and free of heap allocations inside pure elemental array operations.
 

Standard IEEE Intrinsics: Imported ieee_value, ieee_positive_inf, and ieee_negative_inf from ieee_arithmetic. This avoids compiler errors or runtime SIGFPE crashes caused by trying to compute 1.0_real64 / 0.0_real64.

Sign Preservation on Overflow: Added a pure elemental helper function signed_inf(sign_val) so inputs like "-1.80e308" return -Infinity while "1.80e308" returns +Infinity.

Consistent Error 6 Handling: Updated all three overflow return paths (mantissa overflow, total_exp > 308, and the total_exp == 308 boundary check) to assign val = signed_inf(sign_val) alongside ierr = 6.

EXAMPLES

Sample Program: 

  program demo_str_to_real
   use, intrinsic :: iso_fortran_env, only: real64
   use M_unicode__float, only : str_to_real
   implicit none


   character(len=16)  :: inputs(4) = [&
   & "  -42.75 ", &
   & "+1.23e4  ", &
   & "bad_input", &
   & "3.14D-2  "]
   real(real64)       :: values(4), value
   integer            :: errors(4), error
   integer            :: k
   character(len=80)  :: edge_cases(7) = [ character(len=80) :: &
   "1.79e308             Valid: just under real64 max (err: 0)      ",  &
   "1.80e308             Overflow: just over real64 max (err: 6)    ",  &
   "1e999999999999       Overflow: massive exponent string (err: 6) ",  &
   "-1.80e308            -Overflow: and just over real64 max (err: 6)", &
   "0.0e5000             Valid: zero stays zero (err: 0)            ",  &
   "5.0e-324             Valid: subnormal underflow limit (err: 0)  ",  &
   "1.0e-400             Valid: graceful underflow to 0.0 (err: 0)  " ]
   integer            :: iostat
   character(len=256) :: iomsg


   ! Process the entire array in a single elemental call
   call str_to_real(inputs, values, errors)


   do k = 1, size(inputs)
      print ’(A, " -> val: ", G0, ", err: ", I0)’, &
      & trim(inputs(k)), values(k), errors(k)
   enddo


   do k = 1, size(edge_cases)
      print *
      call str_to_real(edge_cases(k)(:20), value, error)
      print ’(A, " -> val: ", G0, ", err: ", I0, 1x, a)’, &
      & trim(edge_cases(k)(:20)), value, error
      print ’("Expected:",A)’, edge_cases(k)(21:)
      iomsg = ’----------------’
      read(edge_cases(k),’(e20.0)’,iostat=iostat,iomsg=iomsg)value
      print *, ’from internal read’,value,iostat,trim(iomsg)
   enddo
  end program demo_str_to_real
