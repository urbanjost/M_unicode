DESCRIPTION

M_unicode__eval is a standard-conforming Fortran 2008 module for compiling, evaluating, and symbolically differentiating mathematical expressions stored as 32-bit Unicode codepoint arrays (integer(int32)).

    CORE DESIGN PRINCIPLES

o Unicode-Native Representation: Expressions and variable names are represented as 1D arrays of integer(int32) Unicode scalar values, eliminating multi-byte UTF-8 indexing bugs.
o Strict Case-Sensitivity: Unlike standard Fortran, all identifiers (sin vs SIN, x vs X, α vs Α) are strictly case-sensitive.
o Compile-Once Bytecode VM: Expressions compile into flat stack-based bytecode (compiled_expr) for fast repeated evaluation inside numerical loops.
o Unified Scalar & Array Broadcasting: All variables are passed as var_value containers (val(:)). Scalars are 1-element arrays (size ==
1) and automatically broadcast against 1D arrays (size == N).

    IMPLICIT MULTIPLICATION RULES

Multiplication is inserted automatically at clear token boundaries: 

   + Number followed by identifier, (, or √: 2x, 3π, 2(x + 1), 5√2.
   + Closing parenthesis ) followed by (, √, identifier, or number:
     (x + 1)(x - 1).
   + Variable or constant followed by ( or √: x(y + 1), π√2.  +
     Note: Adjacent letters like "ab" parse as a single two-character
     identifier, not a * b.
BUILT-IN CONSTANTS 

   + pi or π (U+03C0): π ≈ 3.141592653589793
   + τ (U+03C4): 2π ≈ 6.283185307179586
   + e: Euler’s number ≈ 2.718281828459045
BUILT-IN FUNCTIONS 

   + 1-Argument Element-Wise: sin, cos, tan, asin, acos, atan, sinh,
     cosh, tanh, exp, log, log10, sqrt, abs, floor, ceiling, nint.


   + 2-Argument Element-Wise: atan2(y, x), hypot(x, y), mod(a, p).


   + Variadic Element-Wise / Reduction: min(x) (array min) or
     min(a, b, ...) (element-wise), max(x) (array max) or
     max(a, b, ...) (element-wise).


   + Conditional: if(cond, true_val, false_val) (evaluates true_val
     where cond /= 0, else false_val).


   + Array Reductions & Queries (Return Scalar): sum(x), mean(x),
     norm2(x), dot(x, y), size(x).

EXAMPLES

Sample program 

   program demo_M_unicode__eval
   use, intrinsic :: iso_fortran_env, only: int32, real64
   use M_unicode, only : ctou, utoc, &
   & compiled_expr, cp_string, var_value, user_func, &
   & compile_expr_cp, differentiate_compiled, eval_compiled


   implicit none


   type(compiled_expr) :: prog, dprog
   type(cp_string) :: var_names(3)
   type(var_value) :: vars(3)
   type(user_func) :: custom_fns(1)
   real(real64), allocatable :: res(:), dres(:)
   integer :: err


   ! 1. Register a custom Unicode function:
   1     σ(x) = logistic sigmoid 1 / (1 + exp(-x))
   !
   custom_fns(1)%name%cp = utoc("σ")
   custom_fns(1)%nargs   = 1
   custom_fns(1)%fn      => sigmoid_fn


   ! 2. Define case-sensitive variables:
   !    x = array [1.0, 2.0, 3.0]
   !    X = scalar [10.0]
   !    α = scalar [2.0]
   var_names(1)%cp = utoc("x")
   var_names(2)%cp = utoc("X")
   var_names(3)%cp = utoc("α")


   vars(1)%val = [1.0_real64, 2.0_real64, 3.0_real64]
   vars(2)%val = [10.0_real64]
   vars(3)%val = [2.0_real64]


   ! 3. Array broadcasting + custom Unicode function + array indexing
   call compile_expr_cp(utoc("σ(α·x − x[2]) + X"), prog, err, &
   & var_names, custom_fns)
   call eval_compiled(prog, res, err, vars)
   print *, "Broadcast + Custom Func:", res   ! 3-element array


   ! 4. Array reductions (dot product, sum, norm2)
   call compile_expr_cp(utoc("sum(x²) + x[3] × X"), &
   & prog, err, var_names)
   call eval_compiled(prog, res, err, vars)
   ! 1^2 + 2^2 + 3^2 + 3*10 = 44.0
   print *, "Reduction + Indexing:", res


   ! 5. Symbolic Differentiation: d/dx (x³ + 2x² + sin(x)) ->
   !    3x² + 4x + cos(x)
   call compile_expr_cp(utoc("x³ + 2x² + sin(x)"), &
   & prog, err, var_names)
   call differentiate_compiled(prog, var_idx=1, dprog=dprog, ierr=err)
   call eval_compiled(dprog, dres, err, vars)
   print *, "Analytical df/dx at x=[1,2,3]:", dres


   contains


   function sigmoid_fn(args) result(y)
      real(real64), intent(in) :: args(:)
      real(real64) :: y
      y = 1.0_real64 / (1.0_real64 + exp(-args(1)))
   end function sigmoid_fn


   end program demo_M_unicode__eval

PASSING ARRAYS

Part 2: Passing Arrays To and From the Module in a Larger Code

When integrating ‘M_unicode__eval‘ into a larger simulation or solver (such as a finite-element code, ODE integrator, or optimization loop), you do **not** want to recompile the expression string on every time step or iteration. Instead, follow a **3-phase lifecycle**:

assing Arrays INTO the Module (‘vars(:)%val‘)
o Each variable in your expression corresponds to an index ‘i‘ in ‘var_names(1:N)‘ during ‘compile_expr_cp‘.
o At runtime, you populate ‘vars(i)%val‘—which is a standard Fortran ‘real(real64), allocatable :: val(:)‘ array.
o **For a 1D array variable** (e.g., a grid vector ‘u(1:nx)‘): assign your Fortran array directly (‘vars(1)%val = u‘).
o **For a scalar variable** (e.g., time ‘t‘ or viscosity ‘nu‘): wrap it in a 1-element array constructor (‘vars(2)%val = [t]‘).
o **For multi-dimensional arrays** (e.g., a 2D field ‘T(nx, ny)‘): flatten it into a 1D vector with ‘reshape(T, [nx * ny])‘ when passing it in, then ‘reshape‘ the output back to ‘(nx, ny)‘. Because all arithmetic is element-wise, flattening preserves exact element correspondence.
2. Receiving Arrays FROM the Module (‘result(:)‘)
o ‘eval_compiled(prog, result, ierr, vars)‘ takes ‘real(real64), allocatable, intent(out) :: result(:)‘.
o Fortran automatically allocates ‘result‘ to match the broadcasted size:
o If the expression evaluates to a **vector** (e.g., ‘"nu * u + sin(x)"‘), ‘size(result)‘ equals ‘size(u)‘.
o If the expression reduces to a **scalar** (e.g., ‘"norm2(u) + t"‘), ‘size(result)‘ equals ‘1‘ and the scalar value is ‘result(1)‘.
3. Complete Integration Pattern (Solver Loop Example)
‘‘‘fortran subroutine run_solver_step(x_grid, u_field, dt, t_now, formula_utf8, rhs_out, ierr) use, intrinsic :: iso_fortran_env, only: real64 use M_unicode__eval implicit none

real(real64), intent(in) :: x_grid(:), u_field(:) real(real64), intent(in) :: dt, t_now character(len=*), intent(in) :: formula_utf8 real(real64), intent(out) :: rhs_out(size(x_grid)) integer, intent(out) :: ierr

! Use ’save’ (or store in a solver context struct) to compile only once type(compiled_expr), save :: compiled_rhs logical, save :: is_compiled = .false.

type(cp_string) :: vnames(4) type(var_value) :: vars(4) real(real64), allocatable :: eval_out(:)

! PHASE 1: Compile once on first call if (.not. is_compiled) then vnames(1)%cp = utoc("x") vnames(2)%cp = utoc("u") vnames(3)%cp = utoc("dt") vnames(4)%cp = utoc("t")

call compile_expr_cp(utoc(formula_utf8), compiled_rhs, ierr, vnames) if (ierr /= 0) return is_compiled = .true. end if

! PHASE 2: Pack host Fortran arrays and scalars into var_value containers
vars(1)%val = x_grid
  ! 1D array (size N)
vars(2)%val = u_field
  ! 1D array (size N)
vars(3)%val = [dt]
  ! Scalar wrapped as size-1 array
vars(4)%val = [t_now]
  ! Scalar wrapped as size-1 array
! PHASE 3: Evaluate compiled bytecode and unpack result back into host array call eval_compiled(compiled_rhs, eval_out, ierr, vars) if (ierr /= 0) return

if (size(eval_out) == size(rhs_out)) then rhs_out = eval_out else if (size(eval_out) == 1) then ! Handle case where user’s formula reduced to a constant/scalar (e.g., "0.0") rhs_out = eval_out(1) else ierr = 15 ! Shape mismatch with expected grid size end if end subroutine run_solver_step

Performance Tip for Large Arrays (N > 100,000)

In eval_compiled, every intermediate operation allocates a temporary array tmp(n) on the stack. If you evaluate expressions over massive grids (millions of points) inside a tight inner loop, you can avoid heap allocation churn by either: 

    Chunking (Cache Blocking): Slice your large host arrays
    into L1/L2-cache-friendly blocks of 1024 or 4096 elements
    (x_grid(i:i+chunk-1)), evaluate each chunk with eval_compiled,
    and write directly into rhs_out(i:i+chunk-1).


    Thread-Safe OpenMP Parallelism: Because compiled_expr is read-only
    during eval_compiled and each thread maintains its own local vars
    and stack, you can safely parallelize across chunks using !$omp
    parallel do.
